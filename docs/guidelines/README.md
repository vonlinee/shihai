# 项目开发指南索引

本目录集中存放识海项目的需求基线、系统现状和开发规范。修改项目前，应按任务范围阅读对应文档，不需要按固定顺序通读全部内容。

## 快速查阅

- 设计或调整业务功能：阅读 [需求设计文档](requirements-design.md)；涉及模块边界、权限或数据关系时，同时阅读 [系统设计文档](system-design.md)。
- 修改后端：阅读 [后端指南](backend-guidelines.md) 和 [Go 开发规范](go-development-guidelines.md)。
- 修改前端：阅读 [前端指南](frontend-guidelines.md)。
- 修改跨端功能：同时阅读前后端对应规范，并核对请求、响应和 ID 类型契约。
- 调整权限、角色或后台管理功能：额外阅读 [系统设计文档](system-design.md) 的模块与权限章节。
- 创建 Git 提交：阅读 [Git 提交规范](git-commit-guidelines.md)。

## 文档性质

| 文档 | 性质 | 作用 |
| --- | --- | --- |
| [需求设计文档](requirements-design.md) | 需求基线 | 定义产品目标、当前范围、规划能力和业务规则 |
| [系统设计文档](system-design.md) | 系统现状 | 描述当前架构、模块边界、数据关系和已知差异 |
| [后端指南](backend-guidelines.md) | 开发规范 | 约束后端分层、接口、数据访问、认证和测试 |
| [Go 开发规范](go-development-guidelines.md) | 开发规范 | 约束 Go 代码风格、错误、上下文、并发和测试 |
| [前端指南](frontend-guidelines.md) | 开发规范 | 约束前端组件、状态、请求、样式、路由和表单 |
| [Git 提交规范](git-commit-guidelines.md) | 协作规范 | 约束提交信息、提交流程和分支使用 |

需求文档描述“应该具备什么”，系统设计描述“当前如何实现”。两者不一致时，不应自行把规划内容当成已实现能力；先检查代码和迁移，再确认是补实现还是更新文档。

## 规则优先级

发生冲突时，按以下顺序处理：

1. 用户在当前任务中的明确指令。
2. 根目录 `AGENTS.md` 中的项目级协作规则。
3. 本目录中的专项开发规范和 Git 规范。
4. 需求基线与系统现状等描述性文档。

若采用了与低优先级文档不同的处理方式，应在回复或变更说明中写明原因。

## 文档维护

- 同一规则只在一个专项文档中完整定义，其他文档通过链接引用。
- “必须”用于可验证且项目已经接受的约束；偏好使用“建议”或“优先”。
- 描述当前实现时，应核对代码、依赖、配置、迁移或分支状态；未落地能力必须标记为规划内容。
- 文档文件名使用英文 kebab-case，标题可以使用中文。
- 移动或重命名文档时，必须同步更新本索引和根目录 `AGENTS.md` 中的链接。
- 临时计划、草稿和过程记录不放在本目录；这里只保留长期有效的项目文档。
