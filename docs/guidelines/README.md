# 项目开发指南索引

本目录集中存放识海项目的开发规范、系统设计、需求设计和协作规则。Codex、开发者和其他代码协作工具在修改项目之前，应先根据任务类型阅读对应文档。

## 必读顺序

1. [系统设计文档](system-design.md)：了解系统模块、整体架构和核心设计。
2. [需求设计文档](requirements-design.md)：确认业务目标、功能范围和用户流程。
3. [后端指南](backend-guidelines.md)：修改后端接口、服务、仓储、模型或权限时阅读。
4. [Go 开发规范](go-development-guidelines.md)：编写或调整 Go 代码时阅读。
5. [前端指南](frontend-guidelines.md)：修改前端页面、组件、状态管理或接口调用时阅读。
6. [Git 提交规范](git-commit-guidelines.md)：提交代码前阅读。

## 按任务查阅

- 设计新功能：先读系统设计文档和需求设计文档，再读涉及端的开发规范。
- 修改后端：读后端指南和 Go 开发规范。
- 修改前端：读前端指南。
- 修改跨端功能：同时阅读后端指南、Go 开发规范和前端指南。
- 调整权限、角色或后台管理功能：额外确认系统设计文档中的权限与后台模块说明。
- 提交代码：遵守 Git 提交规范，提交信息使用 `type(scope): 中文说明`。

## 文档维护规则

- 新增长期有效的开发规则时，优先补充到本目录。
- 文档文件名使用英文 kebab-case，文档标题可以使用中文。
- 如果移动或重命名文档，必须同步更新本索引和根目录 `AGENTS.md`。
- 临时计划、草稿和过程记录不要放在本目录；本目录只保留可长期参考的项目指南。
